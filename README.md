# Text analysis pipeline

Программа принимает текст и возвращает JSON: краткое содержание, ровно три
ключевые мысли, категорию, цель автора, настроение, полезный ответ и результат
проверки содержания. Код включает этапы 1–7.

Цепочка: извлечение смысла → классификация → сборка полей → ответ по категории
→ проверка противоречий и потерянных деталей. Категории: `support` — диагностика,
`feedback` — реакция на отзыв, `complaint` — сочувствие и путь решения,
`sales` — помощь с покупкой, `general_question` — ответ или короткий план.

## Структура

- `main.py` — консольный запуск, фильтрация и вывод JSON.
- `llm_client.py` — обращения к API и повторы при временных сбоях.
- `pipeline.py`, `schemas.py`, `prompts.py` — шаги, схемы и инструкции.
- `utils.py` — строгий разбор JSON и сохранение файлов.
- `sample_inputs/` — десять входов и ожидаемые категории для проверки.
- `demo.py`, `examples/` — пять демонстраций с готовыми ответами.
- `tests/` — проверки цепочки, маршрутизации, API и негативных сценариев.
- `compare_prompts.py`, `docs/prompts.md` — сравнение трёх вариантов промпта.

## Установка

Нужен Python 3.10+:

```bash
git clone https://github.com/Rcinderblock/hw2.git
cd hw2
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Демонстрация без ключа

```bash
python demo.py
python demo.py --scenario support --failure invalid_json
python demo.py --scenario complaint --failure missing_fields
python demo.py --scenario sales --failure long_answer
python demo.py --scenario support --failure api_unavailable
```

Пять сценариев: техническая проблема, отзыв, жалоба, покупка и учебный вопрос.
`examples/demo_cases.json` содержит заданные ответы всех шагов; они проходят
через ту же цепочку. Вывод помечен `mode: offline_fixture`, API не вызывается.
Первые три показанные ошибки формата исправляются запасным промптом;
также доступен `--failure empty`. При отказе проверки сохраняются частичные
данные с ошибкой, код завершения — 1. Точность модели эти демонстрации не измеряют.

## Запуск с моделью

```bash
cp .env.example .env
```

Впишите ключ в `.env` вместо `your_api_key_here`. Файл исключён из Git.
`OPENAI_MODEL` задаёт модель, по умолчанию `gpt-4.1-mini`.
Для совместимого сервиса задайте `OPENAI_BASE_URL`; нужны Responses API
и поддержка JSON-схемы. Переменные также можно задать в окружении.

```bash
python main.py --text "Помоги составить план встречи"
python main.py --file sample_inputs/03_support.txt
python main.py --demo --output output/demo.json
python main.py --demo --category feedback --sentiment negative
```

Логи идут в stderr, массив результатов — в stdout. Один успешный цикл делает
четыре вызова модели; `--demo` обрабатывает десять текстов.
Пример входа: «Помоги составить план встречи». Иллюстративный результат:

```json
{
  "summary": "Автор просит помочь спланировать встречу.",
  "category": "general_question",
  "intent": "Составить план встречи",
  "sentiment": "neutral",
  "key_points": ["Нужен план встречи", "Тема не указана", "Участники и время не указаны"],
  "final_answer": "Определите цель и участников встречи, составьте повестку и согласуйте время.",
  "self_check": {"passed": true, "contradictions": [], "missing_details": []}
}
```

## Ошибки и проверка

Все ответы проходят проверку JSON и Pydantic: `summary` до 250 символов,
`intent` до 160, `final_answer` до 400, ровно три разные непустые ключевые мысли.
Сырой ответ ограничен 12 000 символами, генерация — 1200 токенами.

Временные ошибки API повторяются до трёх попыток с увеличением паузы.
Пауза сервера `Retry-After` учитывается; если она больше пяти секунд,
программа предлагает запустить обработку позже. Ошибки доступа и оплаты
не повторяются. Плохой формат получает один повтор с запасным промптом.

Если восстановление не помогло, результат содержит `error` и, при наличии,
`partial_result` с уже проверенными полями. Остальные тексты обрабатываются.
Замечания к содержанию сохраняются как `self_check.passed: false`.
Ошибки видны и при фильтрации; код завершения при них — 1. Проверка моделью
может ошибаться. Входные файлы нельзя заменить через `--output`.
При ошибке сохранения существующий файл результата остаётся целым.

```bash
python -m unittest discover -s tests -v
python compare_prompts.py --output output/comparison.json
```

Тесты работают без ключа. Сравнение требует ключа: при успешных шагах
120 вызовов, повторы увеличивают их число. Реальное сравнение ещё не проведено;
`explicit` выбран предварительно, объяснение — в `docs/prompts.md`.
`--prompt-variant baseline|explicit|example` выбирает первый промпт в `main.py`.
Ожидаемые категории не передаются модели. Результаты из `output/` исключены из Git.
