# Text analysis pipeline

Программа принимает текст и возвращает JSON: краткое содержание, ровно три
ключевые мысли, категорию, цель автора, настроение, полезный ответ и результат
проверки содержания. Код включает этапы 1–7.

Цепочка: извлечение смысла → классификация → сборка полей → ответ по категории
→ проверка противоречий и потерянных деталей. Категории: `support` — диагностика,
`feedback` — реакция на отзыв, `complaint` — сочувствие и путь решения,
`sales` — помощь с покупкой, `general_question` — ответ или короткий план.

## Структура

- `main.py` — консольный запуск, фильтрация и вывод JSON.
- `llm_client.py` — обращения к API и повторы при временных сбоях.
- `pipeline.py`, `schemas.py`, `prompts.py` — шаги, схемы и инструкции.
- `utils.py` — строгий разбор JSON и сохранение файлов.
- `sample_inputs/` — десять входов и ожидаемые категории для проверки.
- `demo.py`, `examples/` — пять демонстраций с готовыми ответами.
- `local_demo.py`, `local_client.py` — запуск настоящей локальной модели.
- `tests/` — проверки цепочки, маршрутизации, API и негативных сценариев.
- `compare_prompts.py`, `docs/prompts.md` — сравнение трёх вариантов промпта.

## Установка

Нужен Python 3.10+:

```bash
git clone https://github.com/Rcinderblock/hw2.git
cd hw2
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Демонстрация без ключа

```bash
python demo.py
python demo.py --scenario support --failure invalid_json
python demo.py --scenario complaint --failure missing_fields
python demo.py --scenario sales --failure long_answer
python demo.py --scenario support --failure api_unavailable
```

Пять сценариев: техническая проблема, отзыв, жалоба, покупка и учебный вопрос.
`examples/demo_cases.json` содержит заданные ответы всех шагов; они проходят
через ту же цепочку. Вывод помечен `mode: offline_fixture`, API не вызывается.
Первые три показанные ошибки формата исправляются запасным промптом;
также доступен `--failure empty`. При отказе проверки сохраняются частичные
данные с ошибкой, код завершения — 1. Точность модели эти демонстрации не измеряют.

## Локальная модель без API-ключа

На Mac с Apple Silicon можно проверить ту же цепочку на настоящей модели:

```bash
pip install -r requirements-local.txt
python local_demo.py --output output/local_demo.json
```

При первом запуске скачивается `Qwen3.5-9B-4bit`, около 6 ГБ. Затем генерация
выполняется локально. Вывод помечен `mode: local_model`; это настоящие
ответы модели, которые проходят обычную проверку схемы и содержания.
Для повторяемости выбраны `temperature=0` и начальное значение генератора 42.
`--samples 03_support 07_refund` выбирает тексты; `--model` меняет модель MLX.

## Запуск с моделью

```bash
cp .env.example .env
```

Впишите ключ в `.env` вместо `your_api_key_here`. Файл исключён из Git.
`OPENAI_MODEL` задаёт модель, по умолчанию `gpt-4.1-mini`.
Для совместимого сервиса задайте `OPENAI_BASE_URL`; нужны Responses API
и поддержка JSON-схемы. Переменные также можно задать в окружении.

Для OpenRouter задайте в `.env` `OPENAI_BASE_URL=https://openrouter.ai/api/v1`
и `OPENAI_MODEL=nvidia/nemotron-3-super-120b-a12b:free`; для воспроизводимой
проверки задайте `OPENAI_TEMPERATURE=0` и `OPENAI_REASONING_EFFORT=none`.
В `OPENAI_API_KEY`
укажите ключ OpenRouter. Доступность бесплатной модели и лимиты зависят от сервиса.
`OPENAI_TEMPERATURE` необязателен: число от 0 до 2, если выбранная модель
поддерживает этот параметр; без него используются настройки сервиса.
`OPENAI_REASONING_EFFORT` также необязателен; `none` отключает внутренние
рассуждения у моделей с такой поддержкой. Для остальных моделей оставьте
его незаданным или выберите поддерживаемый уровень.

```bash
python main.py --text "Помоги составить план встречи"
python main.py --file sample_inputs/03_support.txt
python main.py --demo --output output/demo.json
python main.py --demo --category feedback --sentiment negative
```

Логи идут в stderr, массив результатов — в stdout. Один успешный цикл делает
четыре вызова модели; исправление содержания добавляет ещё два.
`--demo` обрабатывает десять текстов.
Пример входа: «Помоги составить план встречи». Иллюстративный результат:

```json
{
  "summary": "Автор просит помочь спланировать встречу.",
  "category": "general_question",
  "intent": "Составить план встречи",
  "sentiment": "neutral",
  "key_points": ["Нужен план встречи", "Тема не указана", "Участники и время не указаны"],
  "final_answer": "Определите цель и участников встречи, составьте повестку и согласуйте время.",
  "self_check": {"passed": true, "contradictions": [], "missing_details": []}
}
```

## Ошибки и проверка

Все ответы проходят проверку JSON и Pydantic: `summary` до 250 символов,
`intent` до 160, `final_answer` до 400, ровно три разные непустые ключевые мысли.
Сырой ответ ограничен 12 000 символами, генерация — 4096 токенами, включая
внутренние рассуждения модели.

Временные ошибки API повторяются до трёх попыток с увеличением паузы.
Пауза сервера `Retry-After` учитывается; если она больше пяти секунд,
программа предлагает запустить обработку позже. Ошибки доступа и оплаты
не повторяются. Плохой формат получает один повтор с запасным промптом.

Если восстановление не помогло, результат содержит `error` и, при наличии,
`partial_result` с уже проверенными полями. Остальные тексты обрабатываются.
После замечаний к содержанию ответ переписывается один раз и проверяется
снова. Если исправление не помогло, сохраняется `self_check.passed: false`.
Ответ, оборванный на границе 400 символов, получает повтор проверки формата.
Полная смена языка с русского на английский и ответ от имени сервиса
также вызывают повтор с запасным промптом.
Ошибки видны и при фильтрации; код завершения при них — 1. Проверка моделью
может ошибаться. Входные файлы нельзя заменить через `--output`.
При ошибке сохранения существующий файл результата остаётся целым.

```bash
python -m unittest discover -s tests -v
python compare_prompts.py --samples 03_support 07_refund 09_purchase --output output/comparison.json
```

Тесты работают без ключа. Сравнение требует ключа: три выбранных текста
дают 36 основных вызовов; без `--samples` используются десять текстов — 120
вызовов. Повторы увеличивают их число.

Сравнение трёх вариантов выполнено 1 октября 2026 года на одной бесплатной
модели. По отдельному разбору содержания выбран `example`.
[Результаты и обоснование](docs/prompts.md),
[полные ответы и оценки](docs/prompt_comparison.json).
`--prompt-variant baseline|explicit|example` выбирает первый промпт в `main.py`.
Ожидаемые категории не передаются модели. Результаты из `output/` исключены из Git.

## Выполненные этапы и проверки

- 1–2: клиент API, отдельные промпты, ограничения и реальное сравнение трёх вариантов.
- 3–4: строгая JSON-схема, пять категорий и разные инструкции для ответа.
- 5–6: пять последовательных этапов, проверка содержания, исправление,
  повторы API и восстановление формата с сохранением частичных результатов.
- 7: консольный запуск, десять входных текстов и пять демонстраций.

В новом окружении проверены установка зависимостей, 84 автоматических теста,
пять демонстраций и пять негативных сценариев. Пустой ответ, сломанный JSON,
пропущенные поля и превышение длины восстанавливаются; недоступность API
даёт понятную ошибку и сохраняет проверенные поля.

Полная цепочка проверена на настоящей локальной модели: десять разных
текстов, 10/10 правильных категорий, 10/10 валидных результатов и пройденных
самопроверок, 40 вызовов модели. Содержание также разобрано отдельно:
[исходники, ответы всех шагов и оценки](docs/pipeline_validation.json).
Реальный запуск одного сценария также повторён в новом окружении;
проверенные поля совпали с результатом полного прогона.
