# Text analysis pipeline

Программа обрабатывает текст с помощью языковой модели и возвращает JSON:
`summary`, `category`, `intent`, `sentiment`, `key_points`, `final_answer`.

Реализованы этапы 1–4: клиент API, три варианта промпта, проверка JSON,
классификация и выбор инструкций ответа. Первый вызов модели определяет
содержание, категорию, цель пользователя и настроение. После проверки этих
данных код выбирает инструкции для второго вызова, который пишет ответ.
Оба шага используют JSON-схемы и проверку в Python. Содержание ограничено
250 символами, цель — 160, итоговый ответ — 400; ключевых мыслей ровно три.

| Категория | Инструкции ответа |
|---|---|
| `support` | Короткие нумерованные шаги диагностики |
| `feedback` | Признание конкретного отзыва и конструктивная реакция |
| `complaint` | Сочувствие и предложение пути решения проблемы |
| `sales` | Связь потребностей с известными возможностями и следующий шаг |
| `general_question` | Прямой ответ или короткий план действий |

Категория описывает тип обращения, `intent` — конкретную цель автора.
Критика без требования устранить нарушение относится к `feedback`;
жалоба с требованием возврата или разбирательства — к `complaint`.
Настроение: `positive`, `neutral`, `negative`. Категория и настроение также
используются для отбора результатов в консоли.

## Структура

- `main.py` — запуск из командной строки и вывод результата в JSON.
- `llm_client.py` — вызов API модели.
- `prompts.py` — шаблоны классификации и инструкции для каждой категории.
- `pipeline.py` — соединяет этапы и проверяет ошибки.
- `schemas.py` — схемы классификации, ответа и итогового результата.
- `compare_prompts.py` — сравнение вариантов на одинаковых входах.
- `sample_inputs/` — десять текстов и ожидаемые категории для проверки.
- `tests/` — проверки обработки ответа модели без сетевых запросов.
- `docs/prompts.md` — варианты промптов и статус их выбора.

## Запуск

Нужны Python 3.10+ и ключ API. Создайте окружение и установите зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Впишите ключ в `.env` вместо `your_api_key_here`. Файл `.env` исключён из Git.
По умолчанию используется `gpt-4.1-mini`; при необходимости измените
`OPENAI_MODEL`. Для сервиса с поддержкой Responses API и JSON-схемы
задайте `OPENAI_BASE_URL`.

```bash
python main.py --demo
python main.py --demo --output output/demo.json
python main.py --text "Помоги составить план встречи"
python main.py --file /path/to/input.txt
python main.py --demo --prompt-variant baseline
python main.py --demo --category feedback --sentiment negative
```

Программа печатает массив JSON. При ошибке API или невалидном ответе модели
элемент получает поле `error`, а программа завершает работу с кодом 1 после
обработки остальных текстов. Сообщение указывает ошибку JSON или конкретное
неверное поле и этап обработки. Ошибки остаются видимыми при фильтрации.
Обычный запуск `--demo` делает 20 вызовов модели при успешной обработке.
После запуска сопоставьте `category` с `sample_inputs/expected_categories.json`
и проверьте, соответствует ли ответ инструкции выбранной категории.
Ожидаемые категории не передаются модели.

Доступны варианты `baseline`, `explicit` (по умолчанию), `example`.
При необходимости автоматическое сравнение выполняется командой
`python compare_prompts.py`: до 60 вызовов, три варианта на десяти текстах.
`--repeats` задаёт число повторов; `--output` сохраняет отчёт в файл.
Файлы `output/` исключены из Git.

## Проверка

```bash
python -m unittest discover -s tests -v
```

Тесты без сети проверяют выбор инструкций, передачу цели второму шагу и ошибки.
Точность классификации и качество реальных ответов требуют запуска с ключом API.
