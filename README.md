# Text analysis pipeline

Программа принимает текст и возвращает JSON с кратким содержанием,
тремя ключевыми мыслями, категорией, целью автора, настроением и полезным
ответом. Реализованы этапы 1–7.

Одна цепочка: извлечение смысла → классификация → сборка и проверка полей
→ ответ по категории → отдельная проверка содержания по исходному тексту.
Python выбирает инструкции для `support`, `feedback`, `complaint`, `sales`
или `general_question`. Все ответы проверяются схемами Pydantic:
`summary` до 250 символов, `intent` до 160, `final_answer` до 400;
`key_points` содержит ровно три разные непустые строки.

## Установка

Нужен Python 3.10+:

```bash
git clone https://github.com/Rcinderblock/hw2.git
cd hw2
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Демонстрация без ключа

```bash
python demo.py
python demo.py --scenario support --failure invalid_json
python demo.py --scenario complaint --failure missing_fields
python demo.py --scenario sales --failure long_answer
python demo.py --scenario support --failure api_unavailable
```

Пять сценариев: техническая проблема, отзыв, жалоба, покупка и учебный вопрос.
`examples/demo_cases.json` содержит заранее заданные ответы для всех шагов;
`demo.py` проводит их через настоящую цепочку. Вывод помечен
`mode: offline_fixture`. Это проверка работы программы; API не вызывается,
качество модели не измеряется. Также доступен сбой `--failure empty`.
Первые четыре типа ошибок исправляются запасным промптом. При недоступной
проверке сохраняются частичные данные и возвращается код 1.

## Запуск с моделью

```bash
cp .env.example .env
```

Впишите ключ в `.env` вместо `your_api_key_here`. Файл исключён из Git.
Модель задаётся через `OPENAI_MODEL`, по умолчанию `gpt-4.1-mini`.
Для совместимого сервиса задайте `OPENAI_BASE_URL`; нужны Responses API
и поддержка JSON-схемы. Можно задать эти переменные прямо в окружении.

```bash
python main.py --text "Помоги составить план встречи"
python main.py --file sample_inputs/03_support.txt
python main.py --demo --output output/demo.json
python main.py --demo --category feedback --sentiment negative
```

Вход `sample_inputs/03_support.txt`: после обновления не работает экспорт
заметок, перезапуск не помог, сохранить данные нужно до завтрашнего утра.
Иллюстративный ответ из демонстрации (полный результат показывает команда
`python demo.py --scenario support`):

```json
{
  "category": "support",
  "intent": "Найти способ сохранить заметки до завтрашнего утра",
  "sentiment": "negative",
  "key_points": [
    "Экспорт перестал работать после обновления",
    "Перезапуск приложения не помог",
    "Нужно сохранить заметки до завтрашнего утра"
  ],
  "self_check": {"passed": true, "contradictions": [], "missing_details": []}
}
```

`main.py` печатает массив полных результатов: также присутствуют `summary`
и `final_answer`. Логи шагов идут в stderr, JSON — в stdout. Один успешный
цикл делает четыре вызова модели; `--demo` обрабатывает десять текстов.

## Ошибки и восстановление

- Временные сетевые ошибки, тайм-ауты, HTTP 408/409/429/5xx: до трёх попыток
  с увеличением паузы. Встроенные повторы SDK отключены.
- `Retry-After` учитывается. Если сервер требует ждать больше пяти секунд,
  обработка заканчивается сообщением «запустите позже».
- Ошибки доступа, нехватка средств и лимиты расходов не повторяются.
- Пустой ответ, плохой JSON, пропущенные поля, неверные типы и превышение
  длины: один повтор с запасным промптом и той же схемой. Сырой ответ
  ограничен 12 000 символами, генерация — 1200 токенами.
- Если восстановление не помогло, элемент получает `error` и, при наличии,
  `partial_result` с уже проверенными полями. Остальные тексты обрабатываются.
- При замечаниях к содержанию сохраняется результат с
  `self_check.passed: false`. При недоступной проверке положительный вердикт
  не подставляется. Ошибки и отрицательные проверки видны и при фильтрации.

Код завершения 0 означает успешную обработку, 1 — ошибку или непройденную
проверку. Повторы увеличивают количество запросов. Проверяющая модель может
ошибаться и не гарантирует достоверность; API имеет тайм-аут 30 секунд
на попытку, единого ограничения времени всей цепочки нет.

## Структура и проверка

- `main.py`, `llm_client.py` — консольный запуск и API с повторами.
- `pipeline.py`, `schemas.py`, `prompts.py` — шаги, проверки и инструкции.
- `sample_inputs/` — десять входов и ожидаемые категории, не передаваемые модели.
- `demo.py`, `examples/` — пять демонстраций с готовыми ответами и имитацией сбоев.
- `tests/` — успешные цепочки, передача данных, маршрутизация и негативные сценарии.
- `compare_prompts.py`, `docs/prompts.md` — сравнение трёх вариантов промпта.

```bash
python -m unittest discover -s tests -v
python compare_prompts.py --output output/comparison.json
```

Тесты работают без ключа. Сравнение требует ключа: при успешных шагах
120 вызовов; лучший вариант по реальным ответам пока не определён.
`--prompt-variant baseline|explicit|example` выбирает первый промпт в `main.py`.
Сгенерированные результаты из `output/` исключены из Git.
