# Сравнение промптов

Три варианта первого шага извлекают `summary` и ровно три `key_points`:

| Вариант | Формулировка |
|---|---|
| `baseline` | Короткая инструкция с общими ограничениями |
| `explicit` | Ограничения и отдельные указания для каждого поля |
| `example` | Подробные указания и один образец входа и ответа |

## Эксперимент

1 октября 2026 года три варианта прошли всю цепочку на одинаковых входах
`03_support`, `07_refund`, `09_purchase`: техническая проблема, жалоба,
вопрос о покупке. Модель — `nvidia/nemotron-3-super-120b-a12b:free` через
OpenRouter, один запуск на сочетание текста и варианта. Остальные промпты,
JSON-схемы и лимит 1200 токенов одинаковы; остальные параметры генерации
оставлены по умолчанию провайдера. Выполнено 37 вызовов: 36 основных
и один запасной на шаге ответа. API сообщил суммарную стоимость 0.

[Полные входы, снимки промптов, девять ответов, сведения о вызовах
и разбор содержания](prompt_comparison.json) сохранены в репозитории.

| Вариант | Валидный формат после повторов | Верная категория | Проверка моделью | Оценка содержания |
|---|---|---|---|---|
| `baseline` | 3/3 | 3/3 | 3/3 | 15/18 |
| `explicit` | 3/3 | 3/3 | 2/3 | 12/18 |
| `example` | 3/3 | 3/3 | 3/3 | 16/18 |

Оценка содержания составлена ассистентом отдельно от `self_check`:
за каждый текст выставлены 0–2 балла за соответствие извлечения исходным
фактам, сохранение важных деталей и полезность итогового ответа.
Критерии, факты для сверки и комментарии к каждому ответу находятся
в `content_review` отчёта. Эти оценки субъективны; человеческая экспертная
разметка не проводилась.

## Выбор

Выбран `example`, теперь он используется по умолчанию. Он сохранил важные
факты во всех трёх извлечениях и получил 6/6 за соответствие исходному тексту.
У `baseline` в вопросе о покупке появились сведения о скрытых платежах,
продлении и хранилище, которых не было во входе: первый шаг начал отвечать.
У `explicit` уже выполненный перезапуск попал в пункт об отсутствующей
информации. Например, `example` сохранил неудачный перезапуск и срок
сохранения заметок в одном из ключевых пунктов.

Полезность итоговых ответов `baseline` и `example` одинакова по этой оценке —
4/6. У `explicit` ответ о покупке смешал языки и оборвался на словах
«Следующий шаг — запроси»; проверяющая модель отклонила его.

Разбор обнаружил проблемы общих шагов ответа и проверки: незавершённые
слова, неподтверждённые пути меню, переустановку без резервной копии
и обещания операций без доступа к сервису. Общие инструкции уточнены:
ориентир 200–300 символов с завершёнными фразами, сохранение данных
до переустановки и обращение в ответственную службу для реальных операций.
Дополнительные результаты с этими инструкциями сохранены отдельно
в `post_comparison_checks`; исходные девять ответов оставлены без изменений.
Дополнительный ответ о покупке прошёл весь цикл после восстановления формата,
а ответ о технической проблеме проверка отклонила из-за посторонних символов.
Для жалобы отдельно проверена генерация из сохранённых полей: ответ направляет
в поддержку и не обещает выполнить отмену от имени программы.

Это небольшой эксперимент на одной модели и трёх входах, по одному запуску
на каждую пару текста и варианта. Он обосновывает выбор для данного набора,
но не доказывает
статистическое превосходство или стабильность на всех запросах.
Сбой на общем шаге ответа у `example` не доказывает дефект первого промпта.

## Повторный запуск

Задайте API-ключ, модель и адрес сервиса по README, затем выполните:

```bash
python compare_prompts.py --samples 03_support 07_refund 09_purchase --output output/comparison.json
```

При успешных шагах это 36 вызовов; повторы увеличивают число обращений.
Без `--samples` используются все десять входов: 120 основных вызовов.
`--repeats` задаёт число повторов, по умолчанию один.

`format_success_rate` учитывает восстановление формата и не измеряет
успех первой попытки. `best_format_variants` выбирает только по формату;
при ошибках API список пуст. Для окончательного выбора нужно отдельно
проверить содержание сохранённых ответов.
