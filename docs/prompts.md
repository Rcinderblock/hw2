# Сравнение промптов

Три варианта первого шага требуют одинаковые поля: `summary`, `category`,
`intent`, `sentiment`, `key_points`. Ключевых мыслей ровно три,
содержание до 250 символов, цель пользователя до 160 символов.
Второй шаг использует общие для всех вариантов инструкции, выбранные по
категории, и возвращает `final_answer` до 400 символов.

| Вариант | Формулировка |
|---|---|
| `baseline` | Короткая инструкция с общими ограничениями |
| `explicit` | Ограничения и отдельные указания для каждого поля |
| `example` | Подробные указания и один образец входа и ответа |

Для текущего запуска предварительно выбран `explicit`: он явно описывает,
что сделать для каждого поля, и не требует дополнительного примера.
Это выбор по устройству инструкции. Лучший вариант по ответам модели пока
не определён: реальное сравнение не проводилось.
Рост качества или стабильности не подтверждён.

Сравнение можно провести вручную в доступном чате с моделью: использовать
одни и те же тексты для трёх вариантов, затем применить выбранные инструкции
ответа и кратко записать наблюдения. Для автоматического сравнения через API:

```bash
python compare_prompts.py
```

Все три варианта проходят один пайплайн на десяти одинаковых текстах.
При успешных шагах это 60 вызовов модели: 3 варианта × 10 текстов × 2 шага.
Число повторов задаётся через `--repeats`, по умолчанию один. Вывод содержит
ответы, отказы схемы и отдельные ошибки API; файл через `--output` необязателен.
Сравниваем долю валидных результатов, сохранение основных фактов, правильность
категории, полезность ответа и отсутствие выдуманных подробностей.
Длины отражают краткость; более короткий ответ сам по себе не считается лучшим.

`best_format_variants` перечисляет варианты с наибольшей долей соблюдения
формата; при равенстве остаются все. При ошибках API список пуст, поскольку
сравнение неполное. Окончательный выбор требует просмотра содержания ответов.
