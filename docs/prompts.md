# Сравнение промптов

Три варианта первого шага извлекают одинаковые поля: `summary`, `key_points`.
Ключевых мыслей ровно три, содержание до 250 символов.
Остальные шаги одинаковы: классификация, сборка полей, ответ по категории
и проверка содержания по исходному тексту.

| Вариант | Формулировка |
|---|---|
| `baseline` | Короткая инструкция с общими ограничениями |
| `explicit` | Ограничения и отдельные указания для каждого поля |
| `example` | Подробные указания и один образец входа и ответа |

Предварительно выбран `explicit`: он явно описывает работу с каждым полем
и не требует дополнительного примера. Это выбор по устройству инструкции.
Лучший вариант по ответам модели пока не определён: реальное сравнение
не проводилось, рост качества и стабильности не подтверждён.

Сравнение можно провести вручную в доступном чате с моделью: использовать
одни и те же тексты, затем последовательно применить инструкции остальных
шагов и кратко записать наблюдения. Автоматическое сравнение через API:

```bash
python compare_prompts.py
```

Три варианта проходят всю цепочку на десяти одинаковых текстах.
При успешных шагах это 120 вызовов: 3 варианта × 10 текстов × 4 вызова.
При сбоях число обращений может увеличиться из-за повторов API и запасного
промпта. Метрики учитывают результат всей цепочки после восстановления,
поэтому не измеряют долю удачных ответов с первой попытки.
Число повторов задаётся через `--repeats`, по умолчанию один.
Вывод содержит результаты и статусы `ok`, `invalid_response`, `api_error`,
`self_check_failed`. Файл через `--output` необязателен.

`format_success_rate` считает структурно валидные результаты, включая те,
которые не прошли проверку содержания. `self_check_failures` отдельно считает
отрицательные заключения проверяющей модели; это её оценка, а не независимое
доказательство ошибки. При просмотре учитывайте сохранение фактов,
правильность категории, полезность ответа и замечания проверки.

`best_format_variants` перечисляет варианты с наибольшей долей соблюдения
формата; при равенстве остаются все. При ошибках API список пуст, поскольку
сравнение неполное. Окончательный выбор требует просмотра содержания ответов.
